Squeezing a 6 GB card

What was tried on one small GPU in one day, what stuck, what did not, and how to repeat the overclock on your own hardware. Everything opens on demand.

What the tuning bought

Speed-up in generated tokens per second, kept changes only. Dashed line is 1x. Click a row for its before and after.

speculative decodinglayers and KV cache settingGPU clocks
  • Models: R1-distill-Qwen 7B Q4_K_S, Qwythos 9B Q4_K_M, Qwen2.5 3B Q5_K_M. The 9B keeps part of its layers on the CPU.
  • Speculative rows use the built-in ngram-simple on a prompt that asks for one changed function and prints the whole file again. The answer text matched the run without it. Plain questions did not speed up or slow down. The 7B thinks first, so it gained nothing there.
  • Layer and KV rows combine two changes: more layers on the GPU after a display moved to the iGPU, and the 7B value cache stored at 4 bits with the key cache at 8 bits. Perplexity moved 8.181 to 8.204, inside its +/-0.14 error.
  • The clocks row is the 7B at a 4K context, from a 100 W power limit with stock clocks to 120 W with memory +2300 and core +105 offsets.
  • Single passes of 3 repetitions. Differences under about 3% are noise. The 7B 15K before and after come from two runs hours apart.
  • The first overclock run (100 W) logged power readings that were too low because the sampler was fixed afterwards. The 12:29-12:39 system runs are labelled from file names (pl100, lgc, mo250, thp), read as 100 W limit, locked clocks, memory offset +250 and huge pages. The 13:56 full run came right after the soak with the offsets still active; I did not read them back, so its gain is probably the overclock.
  • The lab.py suite runs (10:18-10:25) are not charted. TRIALS.md has no figures for them.
