Making an older graphics card answer faster

This PC runs AI chat models on its own hardware. Its graphics card, a GTX 1660 Ti, is old and has little memory. This page lists every experiment that was tried to make the answers come faster, and what happened to each one.

Two speeds matter. Reading is how fast the PC takes in your question. Writing is how fast it types the answer. Both are counted in tokens per second. A token is a word or a piece of a word. The models are named by size: 1.3B is the smallest and 9B the largest.

How many layers go on the card, with a 16 thousand token context and q8_0 KV cache. Dark grey is the old gateway setting, blue the count picked in this trial. More layers are faster until the context no longer fits. The 7B has since moved to all 29 layers with K q8_0 / V q4_0 (decision ledger).

ngram-simple (--spec-type)Trial charts: copy what the prompt already says.

The server guesses the next tokens from text already in the conversation and checks them in one batch. It helps when the answer repeats the prompt and costs nothing when it does not. Dark grey is off, blue is on.

The kernel fix, build by buildPer-run tables and charts for the six code states, KV matrix, timing, stability, code diff.

The first and largest change: the card was running tensor-core kernels it does not have. Six code states were measured before the final one shipped. All bars are tokens per second and longer is better, unless the panel says otherwise. The small black mark on a bar is the spread between repetitions.

6

Build 6 is the one to keep. It reads prompts 3 to 4 times faster, writes at the same speed, no longer runs out of video memory at 8K, and gives the same answers. The only cost is one case, f16 memory on the GPU with a long chat, which writes 7% slower.

Each cell is the typical (median) change against the starting build measured in the same session. better no real change, within 3% worse not measured. The charts below show every individual number.

Why the final build picks a different attention kernel

With the fix in place the f16 store cannot use the tensor-core kernel. Two others remain. These runs isolate them on the same build.
